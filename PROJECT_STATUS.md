# Project Status — Cognitive Load Estimation from EEG + fNIRS

_Last updated: 2026-08-25 · branch `phase2`_

## What this project is

A hybrid deep-learning model that fuses **EEG** (electrical) and **fNIRS**
(hemodynamic) brain signals from the TU Berlin open n-back dataset (26
subjects) to estimate mental workload. Two labeling regimes exist:

- **Binary** (Low vs High) — the currently served, actively-improved model.
- **3-class** (Low / Medium / High) — the original model, kept in
  `serving_3class/` and on the Research page for comparison.

It ships as a full demo: FastAPI backend (`backend/`) + React/Vite frontend
(`frontend/`), with **every number the UI shows traceable to a committed
artifact** — nothing is hardcoded. The project's throughline is methodological
honesty: cross-subject (leave-one-subject-out, LOSO) accuracy is reported
front and center, and it is meaningfully lower than a fixed train/test split
would suggest, because a fixed split leaks subject identity.

## Current headline results

### Binary model (served now)

Served bundle numbers come from `run_20260820_141126_19cb`, mirrored into
`serving/frontend_data/metrics.json`:

| Protocol | Accuracy | Macro F1 | ROC-AUC |
|---|---:|---:|---:|
| LOSO, 26 subjects (4,576 pooled held-out windows) | **63.09% ± 10.1%** | 0.6255 | 0.6775 |
| Lockbox (8 fully unseen subjects, evaluated once) | 63.71% ± 8.5% | 0.6275 | 0.6888 |

- Fairly balanced per class: Low recall 68.2%, High recall 58.0%.
- Train macro F1 ~0.80 vs ~0.63 held-out — a real ~17-point generalization
  gap, even though the held-out numbers are leakage-audited.
- Per-subject accuracy varies widely (subject 17 reaches 80.7%, subject 12
  falls to 44.9%) — the 63% average masks real between-subject variance,
  expected for EEG/fNIRS.
- Source of truth: `RESULTS_BINARY_IMPROVEMENT.md` (generated by
  `research/report.py`, never hand-edited).

## Search history: 58 configurations, still no accepted improvement

The binary model has now been attacked in three separate campaigns. All three
used the same discipline: **18-fold development LOSO is the only selection
signal**, the 8-subject lockbox is touched only to confirm a promoted winner,
and a candidate is adopted only if it clears the baseline by at least one
standard error.

| Campaign | Driver | Configs | Outcome |
|---|---|---:|---|
| Original improvement campaign | `run_campaign.py` | 42 | none cleared the one-SE bar |
| Target campaign | `target_campaign.py` | 15 | none cleared on dev; best (D2) promoted and rejected on full protocol |
| Deep-ensemble screen | `ensemble_campaign.py` | 1 | **first candidate to clear the dev-screen bar** — awaiting full-protocol confirmation |

### Target campaign (`run_20260823_100232_81fe`, `run_20260823_134721_def6`)

15 candidates deliberately chosen to probe axes the original 42 never touched:
joint changes (two axes moved together, where the 42-list moved one at a
time), capacity points between the baseline and the narrow arm, batch size 32,
and shorter early-stop patience. Full row-by-row record:
`outputs/runs/target_campaign_log.md`.

Every candidate was rejected on the development screen. Several landed inside
the baseline's noise floor (C2 0.6430, C9 0.6414, C10 0.6539, C11 0.6476,
D2 0.6471 dev-LOSO accuracy) but none cleared the bar.

**Environment caveat, recorded rather than smoothed over.** The baseline
reconfirmation arm (`A0_baseline_reconfirm`) scored **0.6304 ± 0.1019**
dev-LOSO accuracy / **0.6211 ± 0.1062** macro F1, against the documented
baseline's 0.6537 ± 0.075 / 0.6451 ± 0.078 in
`RESULTS_BINARY_IMPROVEMENT.md`. The log flags this as `MISMATCH vs
documented baseline`. The campaign therefore compares candidates against the
**in-run** baseline, not the documented one, so the comparison stays paired
inside a single environment. Both numbers are reported; neither is discarded.

### D2 promotion — the full protocol overturned the dev screen

`D2_narrow_patience6` (narrow capacity, `proj_dim`/`enc_dim` 32,
`fc_units [32]`, early-stop patience 6; 66,114 params vs the baseline's
~246k) was the strongest interpolated candidate, so it was promoted through
`finalize_winner.py` to the headline protocol. That run
(`run_20260823_173425_b133`) re-ran the **untouched baseline through the same
two protocols in the same environment**, so the comparison is paired and free
of cross-run noise.

| Protocol | Model | Accuracy | Macro F1 | ROC-AUC |
|---|---|---:|---:|---:|
| 26-fold LOSO | baseline | **0.6366 ± 0.0924** | **0.6317 ± 0.0931** | 0.6940 |
| 26-fold LOSO | D2 candidate | 0.6333 ± 0.0974 | 0.6271 ± 0.0977 | **0.6986** |
| Lockbox (8 subj) | baseline | **0.6449 ± 0.0964** | **0.6393 ± 0.1018** | 0.6798 |
| Lockbox (8 subj) | D2 candidate | 0.6271 ± 0.1140 | 0.6172 ± 0.1202 | **0.6839** |

Paired significance over folds:

| Comparison | Mean diff | Wins/losses | t p | Wilcoxon p | Significant |
|---|---:|---:|---:|---:|---|
| 26-fold LOSO, D2 − baseline | −0.0047 | 14 / 12 | 0.700 | 0.960 | no |
| Lockbox, D2 − baseline | −0.0221 | 2 / 6 | 0.218 | 0.195 | no |

**Verdict: not adopted.** D2 wins on the dev screen and on AUC, loses on
accuracy and F1 on both headline protocols, and none of it is significant.
The baseline is retained. D2's one genuine advantage is a smaller
generalization gap (14.4 pts vs the baseline's 17.0 pts train−heldout macro
F1) at roughly a quarter of the parameters — recorded as a finding, not a
promotion.

### Deep-ensemble screen — the first candidate to clear the bar

`ensemble_campaign.py` trains **5 independently-seeded copies** of the served
architecture per fold and averages their softmax outputs (a standard deep
ensemble, Lakshminarayanan et al. 2017). This is mechanistically distinct from
everything in the 57-config history: every prior attempt changed one model's
capacity, regularization or data, whereas this reduces variance across
independent initializations without changing any single model.

Development screen (`run_20260823_192014_57f9`, 18 folds, 5 members,
1,227,970 total params, 73 min):

| Metric | In-run baseline (A0) | 5× ensemble | One-SE bar | Result |
|---|---:|---:|---:|---|
| Accuracy | 0.6304 ± 0.1019 | **0.6632 ± 0.0988** | 0.6544 | clears by +0.0088 |
| Macro F1 | 0.6211 ± 0.1062 | **0.6546 ± 0.1054** | 0.6461 | clears by +0.0085 |
| ROC-AUC | 0.6787 ± 0.1340 | **0.7122** | 0.7103 | clears by +0.0019 |

The ensemble also beats its own mean solo member by **+4.8 accuracy points**
(0.6632 vs 0.6149), which is the expected variance-reduction signature rather
than a data artifact. The fold-level leakage audit passed on all 18 folds.

**Four caveats, all load-bearing:**

1. It clears the *in-run* baseline. Against the **documented** baseline
   (0.6451 ± 0.078 dev-LOSO F1) the same numbers **fail** the one-SE bar by
   −0.0089 F1. Which baseline is correct is the open question flagged above.
2. The margins are thin — AUC clears by 0.0019. No paired significance test
   has been run for this comparison yet.
3. Per-class behaviour got **worse-balanced**: Low recall 80.1% / High recall
   52.6%, versus the baseline's 71.5% / 55.9%. The accuracy gain is partly
   bought by leaning harder on the majority-predicted class.
4. Train−heldout macro F1 gap widened to 22.9 pts (baseline 17.0).

**Status: not promoted, not served.** The `--stage final` run (26-fold LOSO +
lockbox) has not been executed. Until it is, the served model is unchanged.

```
dann.py, dann_ablation.py, NOVELTY_DANN.md                       domain-adversarial (DANN) contribution + ablation — not adopted
research/                                                        leakage-audited experiment framework for the BINARY model
  datamod.py, leakage.py, archs.py, train.py, metrics.py, ...    preprocessing contract, leakage assertions, model zoo, run archive
run_campaign.py                                                  CLI driving the original 42-experiment binary campaign
target_campaign.py                                               15 follow-up candidates probing axes the 42 never touched
finalize_winner.py                                               promote ONE dev winner to 26-fold LOSO + lockbox, paired against a same-run baseline
ensemble_campaign.py                                             5-member deep-ensemble screen (--stage dev | final)
outputs/runs/                                                    per-run archive (metrics, predictions, figures, models) — never overwritten
outputs/runs/target_campaign_log.md                              one row per attempt, win or lose
export_for_serving.py, export_research_data.py                   package frozen model + eval artifacts -> serving/
export_binary_reliability.py                                     parse RESULTS_BINARY_IMPROVEMENT.md -> extra keys in serving metrics.json
serving/, serving_3class/                                        committed portable demo bundles (weights, scaler, RF, demo samples, frontend_data/*.json)
backend/                                                         FastAPI serving API (runs_service.py reads outputs/runs/)
frontend/                                                        React + Vite demo UI
RESULTS.md, RESULTS_BINARY_IMPROVEMENT.md, NOVELTY_DANN.md       results + methodology narrative
explanation/PROJECT_RECORD.md (+ PDFs)                           full written record: architecture, every experiment, all results
```

Key design property of `research/`: every fold runs leakage assertions
(subject/trial/window/duplicate-row/scaler-fit/held-out-subject disjointness)
**before** training; a failure raises `LeakageError` and aborts the run, so a
leaked score can never be produced. Metrics are recomputed from each run's
saved `predictions.csv` and verified to match (`research.verify_run`). The
negative tests in `research/test_leakage.py` inject each leakage type
deliberately and confirm the audit fires — an audit that never fires would
prove nothing.

## Honest limitations (already documented, still true)

- Per-subject normalization is a demo-mode simplification: the model
  normalizes each subject against that subject's own precomputed stats,
  which don't exist for a genuinely new person.
- Only 26 subjects total — small for cross-subject generalization claims.
- The "sustained-engagement" band in the trend view is literature-informed
  context (Yerkes–Dodson), not a clinical threshold.
- CSV upload only accepts already-extracted TU-Berlin-format features, not
  raw signals or other datasets/devices.
- The documented-vs-reconfirmed baseline mismatch (above) is unresolved. Every
  comparison since is paired within a single run to route around it, but the
  absolute baseline figure carries that uncertainty.
